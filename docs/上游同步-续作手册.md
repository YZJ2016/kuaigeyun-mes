## 工作方法（沿用）

1. 每批：取上游 diff → 本地独有内容核对 → 整取或手术 → `py_compile`/esbuild → 聚焦 pytest → 台账 verdict+note → `docs/上游同步台账.md` 追加批次 → commit+push `origin develop`
2. 验证命令：
   - `cd riveredge-backend && uv run pytest <聚焦测试> -x -q`
   - `cd riveredge-backend && python scripts/scan_timezone_contract.py --fail-on high`
   - `cd riveredge-frontend && python scripts/scan_unitable_row_cache.py --fail-on high`
3. 整取前必查 `git diff gitee/develop HEAD -- <file> | grep -E '^[+][^+]'` 的本地独有行（kuaicaiwu/品牌/review_submitted/本地硬化）
4. 上游 types.py 的 capabilities 新字段是**必填**——任何构造该模型的 policy 文件都必须同步补字段，否则 pydantic ValidationError（本批已踩过并修复）

## 已知坑

- `git diff gitee/develop HEAD` 中 `-`=上游 `+`=本地，方向别搞反
- `git diff A B` 不含工作区改动；批量 verdict 更新后要复查 `$3` 列是否合法 verdict
- 前端 esbuild 有环境噪声（别名/wasm），只看目标文件报错
- 上游测试可能自带 fixture/mock 缺陷，按本地惯例补 `in_transaction` noop mock
- `apps.kuaizhizao.print.designer_presets` 导入链在裸 import 时可能报 `未定义设计器布局`——环境问题非本批引入
